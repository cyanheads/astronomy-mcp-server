# 0.3.1 — 2026-09-23

## Added

- **`astronomy_get_ephemeris`: `target_name`** — the object Horizons actually resolved the designation to, parsed from its `Target body name:` header. A bare name can resolve to an unrelated object (`Eros` → Kerberos, a moon of Pluto); compare `target_name` against the one intended. ([#32](https://github.com/cyanheads/astronomy-mcp-server/issues/32))
- **`astronomy_get_satellite_passes`: a fixed alias table** resolves ISS / International Space Station, Hubble / Hubble Space Telescope / HST, and Tiangong / CSS / Chinese Space Station directly to their catalog numbers, ignoring case and whitespace, before any CelesTrak `NAME=` search. ([#39](https://github.com/cyanheads/astronomy-mcp-server/issues/39))

## Fixed

- **`astronomy_get_ephemeris`** — an offset-bearing `start`/`stop` was forwarded to Horizons verbatim, which cannot read a numeric UTC offset and replies `Cannot interpret date`; that refusal was then misread as `body_not_found`. Horizons now receives the parsed UTC instant. ([#31](https://github.com/cyanheads/astronomy-mcp-server/issues/31))
- **`astronomy_get_ephemeris`** — a span outside the target's own Horizons data (e.g. Mars ends after A.D. 2599-DEC-31) was also misread as `body_not_found`. It now fails as `time_out_of_range`, with Horizons' own bound in the message. ([#43](https://github.com/cyanheads/astronomy-mcp-server/issues/43))
- **`astronomy_get_satellite_passes`** — a pass rising inside the search window but setting after it closed was dropped entirely instead of reported through its real set; the scan now keeps stepping through an open pass, bounded to one orbital period. ([#33](https://github.com/cyanheads/astronomy-mcp-server/issues/33))
- **`astronomy_get_satellite_passes`**: `format()` heading now reads "1 visible pass" in the singular.
