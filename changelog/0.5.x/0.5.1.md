# 0.5.1 — 2026-11-16

## Added

- **`meteor_shower` event class on `astronomy_find_events`** ([#71](https://github.com/cyanheads/astronomy-mcp-server/issues/71)): the maxima of nine major annual showers from a bundled IMO table, each with `zhr`, the J2000 radiant, activity dates, and `moon_illuminated_fraction`. A `shower` input narrows the search to one by code or name (`shower_not_found` on a miss), and an observer adds `radiant_altitude_degrees` and `sun_altitude_degrees` at the maximum. The `astronomy_stargazing_plan` prompt gains a step that checks showers around the night.
- **`star` input on `astronomy_get_rise_set`** ([#70](https://github.com/cyanheads/astronomy-mcp-server/issues/70)): rise, set, and transit for a catalog star, taking the names `astronomy_get_sky_position` accepts (`star_not_found` on a miss). It wins over `body` and returns no twilight.
- **`contacts_local` on `astronomy_find_events` eclipses** ([#69](https://github.com/cyanheads/astronomy-mcp-server/issues/69)): with a `timezone`, each contact keyed `<phase>_local`, using the zone offset in force at that contact's own instant.
- **`constellation`, `sun_elongation_degrees`, and `visibility` on each `astronomy_get_ephemeris` row** ([#72](https://github.com/cyanheads/astronomy-mcp-server/issues/72)): elongation is measured from the observer when `latitude` and `longitude` are given, else from Earth's center; `visibility` is `morning`, `evening`, or null.

## Changed

- **`astronomy_get_rise_set` with neither `body` nor `star`** now fails with reason `body_required` (was `invalid_arguments`; still -32602).
- **`astronomy-guide` skill 1.0 → 1.1**: adds meteor-shower guidance, rise/set for stars, and the J2000 note for ephemeris RA/Dec.

## Fixed

- **`astronomy_get_ephemeris` RA/Dec frame** ([#68](https://github.com/cyanheads/astronomy-mcp-server/issues/68)): `ra_hours` and `dec_degrees` were unlabeled astrometric ICRF (J2000) values, unlike `astronomy_get_sky_position`'s apparent of-date coordinates. The field descriptions, tool description, and `content[]` header (`RA/Dec astrometric ICRF (J2000)`) now say so; values are unchanged.
- `astronomy_find_events` `content[]` shows a null eclipse phase as `none` instead of dropping it.
- A one-row `astronomy_get_ephemeris` header reads `— 1 point`, not `— 1 points`.
