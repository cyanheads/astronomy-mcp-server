# 0.5.0 — 2026-10-28

## Added

- **`astronomy-guide` skill** (`skills/astronomy-guide/SKILL.md`): chains the `astronomy_*` tools for observing questions — anchoring dates to the observer's local night, what each tool means by visible, Moon interference, eclipses from a place, the 1900–2100 span, and the opt-in Horizons and satellite tools. Served over MCP as `skill://astronomy-guide/SKILL.md` with the `skill://{+path}` template through `createApp({ skills })` (mcp-ts-core 0.13.18), and ships in the npm package, the Docker image, the `.mcpb`, and plugin installs.
- **Root Agent Plugins manifest pair**, `plugin.json` + `mcp.json` (template from mcp-ts-core 0.13.18).

## Changed

- **The `.mcpb` carries only the runtime files**: the root `README.md`, `LICENSE`, `CHANGELOG.md`, `manifest.json`, `package.json`, and `server.json`, plus `dist/`, `skills/`, and `node_modules/`. 0.4.3's bundle also shipped `src/`, `scripts/`, `changelog/`, `docs/`, `.github/`, `.vscode/`, the `.claude-plugin/` and `.codex-plugin/` directories, `CLAUDE.md`, `AGENTS.md`, `CITATION.cff`, `devcheck.config.json`, `.gitattributes`, `.dockerignore`, and the framework package's build-only files. The root-anchored `.mcpbignore` and the `clean-mcpb` build-only stripping (mcp-ts-core 0.13.18) account for it. The bundle cleaner keeps the MCP SDK's `dist/ext/skills/` runtime, which a skills-serving bundle needs at startup, as a local workaround for open upstream [cyanheads/mcp-ts-core#794](https://github.com/cyanheads/mcp-ts-core/issues/794).
- **`visibility_note` output-field description**: the example uses an 8-point compass label (`W`), the precision the server emits (it showed `WSW`). `docs/design.md` corrects its star-catalog description (a 32-star in-source table) and its `astronomy_list_visible` bounds and field notes.
- **Repo upkeep**: framework skills and scripts resynced (`add-skill` new), issue templates, and the `bunfig.toml` `minimumReleaseAge` guard at 1 day (template, mcp-ts-core 0.13.17).

## Fixed

- On mcp-ts-core 0.13.16, which 0.4.3 shipped with, the HTTP transport retained memory for every request, so an HTTP deployment running under Bun — the runtime of the Docker image — grew until it ran out of memory. mcp-ts-core 0.13.17 releases each request's resources when its response ends ([cyanheads/mcp-ts-core#786](https://github.com/cyanheads/mcp-ts-core/issues/786)).
