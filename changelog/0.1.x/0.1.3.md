# 0.1.3 — 2026-06-28

Presentation pass on the `content[]` markdown twin plus prompt-injection hardening on the stargazing prompt.

## Added

- **`astronomy_get_rise_set`** — `body` output field, echoed from the request, so `content[]`-only clients see which body the rise/set cycles describe. ([#3](https://github.com/cyanheads/astronomy-mcp-server/issues/3))

## Changed

- **`astronomy_get_rise_set`** — `format()` leads with `## <body> — <n> rise/set cycles` and renders each cycle as one numbered line (`Rise … · Set … · Transit …`), with the transit altitude rounded to one decimal. ([#3](https://github.com/cyanheads/astronomy-mcp-server/issues/3))
- **`astronomy_find_events`** — `content[]` opens with a `## <n> events found` count line; per-event headings drop from `##` to `###`. ([#3](https://github.com/cyanheads/astronomy-mcp-server/issues/3))
- **`astronomy_list_visible`** — each body leads with its `visibility_note` headline, followed by one compact line of rounded coordinates in place of the multi-line raw-field-name dump; full precision still rides `structuredContent`. ([#3](https://github.com/cyanheads/astronomy-mcp-server/issues/3))
- **`astronomy_get_satellite_passes`** — `content[]` rounds pass azimuths and peak altitude to one decimal and duration to whole seconds (`az 230.3°`, not `az 230.26515812203434°`). ([#3](https://github.com/cyanheads/astronomy-mcp-server/issues/3))
- **`astronomy_stargazing_plan`** — wraps user-supplied `location` and `date` in `<location>`/`<date>` tags framed as data, not instructions, and references them generically in the numbered steps so an instruction-like value is no longer re-interpolated into the workflow. ([#6](https://github.com/cyanheads/astronomy-mcp-server/issues/6))
