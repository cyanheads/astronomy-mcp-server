# 0.1.1 — 2026-06-25

Initial release of `@cyanheads/astronomy-mcp-server`. Observational astronomy computed in-process via `astronomy-engine` — keyless, offline, and deterministic for a given `(body, time, observer)`. The five core tools, the body resource, and the stargazing prompt need no configuration; two network-backed extensions register only when their gate is enabled, so the default deployment needs no API key and makes no network calls.

## Added

- **`astronomy_get_sky_position`** — apparent topocentric position of one solar-system body or a named bright star: equatorial (RA/Dec), refraction-corrected horizontal (alt/az), and ecliptic coordinates, plus distance, magnitude, angular diameter, phase angle, illuminated fraction, and constellation.
- **`astronomy_get_rise_set`** — rise, set, and culmination times with transit altitude; the three twilight pairs (civil −6°, nautical −12°, astronomical −18°) for the Sun; circumpolar and never-rises cases reported as null fields with an explanatory note.
- **`astronomy_get_moon_phase`** — illuminated fraction, phase name, synodic age, phase angle, and the next four quarter phases.
- **`astronomy_find_events`** — forward search across nine event classes: solar/lunar eclipses, equinoxes, solstices, moon quarters, oppositions, conjunctions, greatest elongations, and apsides.
- **`astronomy_list_visible`** — one-call "what's up now" list of naked-eye bodies (and optional catalog stars) above the horizon, ranked with a plain-language visibility note and gated by the Sun's altitude into daylight / twilight / dark.
- **`astronomy://body/{body}`** resource — static reference card (canonical name, type, mean radius, naked-eye visibility) for each supported body.
- **`astronomy_stargazing_plan`** prompt — chains the tools into a "plan tonight's stargazing from <place>" workflow and names the cross-server geocoding and weather steps.
- **`astronomy_get_ephemeris`** — gated extension (`ASTRONOMY_ENABLE_HORIZONS`): time-series ephemerides for small bodies (asteroids, comets) and spacecraft from JPL Horizons, covering objects the in-process major-body engine cannot.
- **`astronomy_get_satellite_passes`** — gated extension (`ASTRONOMY_ENABLE_SATELLITES`): visible satellite passes over an observer, from a CelesTrak TLE propagated with SGP4 in-process.
- **Optional extension config** — `ASTRONOMY_ENABLE_HORIZONS`, `ASTRONOMY_ENABLE_SATELLITES`, and `ASTRONOMY_DEFAULT_TIMEZONE` declared in `server.json`, with base-URL, request-timeout, and TLE-cache-TTL overrides documented in `.env.example`.
