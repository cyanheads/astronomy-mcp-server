# 0.1.2 — 2026-06-27

Bug-fix release for the two gated extension tools and `astronomy_list_visible`.

## Fixed

- **`astronomy_get_ephemeris`** — topocentric calls (with observer `latitude`/`longitude`) failed with a `SerializationError` and `distance_au: NaN`. The JPL Horizons request now adds the azimuth/elevation quantity for an observer — `QUANTITIES '1,4,9,20'` topocentric, `'1,9,20'` geocentric — so the CSV columns align and `delta` parses to a finite distance. ([#1](https://github.com/cyanheads/astronomy-mcp-server/issues/1))
- **`astronomy_get_ephemeris` / `astronomy_get_satellite_passes`** — an unparseable `start` returned a generic error on the ephemeris tool and a silently empty, falsely-successful pass list on the satellite tool. Both now reject bad timestamps up front with an `invalid_time` `InvalidParams` error before any network call; satellite passes routes `start` through `resolveTime()` and also enforces the SGP4 1900–2100 span (`time_out_of_range`). Ephemeris validates parseability only, since Horizons spans epochs outside the core engine's high-accuracy range. ([#5](https://github.com/cyanheads/astronomy-mcp-server/issues/5))
- **`astronomy_list_visible`** — the default list iterated every entry in `BODY_META`, surfacing telescopic Uranus, Neptune, and Pluto despite the advertised naked-eye surface. `listVisible()` now skips bodies marked `nakedEye: false`. ([#4](https://github.com/cyanheads/astronomy-mcp-server/issues/4))
- **`astronomy_list_visible`** — `sky_condition`, `sun_altitude_degrees`, and `total_count` were emitted only as enrichment, so `content[]`-only clients never saw the sky-condition gate. They now ride `ListVisibleOutput`, and `format()` opens with a `Sky: <condition> (Sun <alt>°) — <n> bodies visible` header. ([#2](https://github.com/cyanheads/astronomy-mcp-server/issues/2))
