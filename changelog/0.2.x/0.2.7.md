# 0.2.7 — 2026-08-18

## Fixed

- **`astronomy_get_rise_set`** — a cycle already in progress at `start` no longer pairs a set with the following day's rise; that first cycle now reports as a partial cycle (null `rise`, the imminent `set`). Two related defects in the same code path are fixed alongside it: the search cursor advanced a full day past the rise, overshooting the next set for early-rising bodies and dropping a cycle on multi-`count` calls, and the Sun's twilight pair was searched from that same cursor instead of the cycle's own rise. ([#20](https://github.com/cyanheads/astronomy-mcp-server/issues/20))
- **`astronomy_stargazing_plan`** — each step that picks a time now anchors it to the requested date in the observer's resolved IANA zone rather than UTC midnight, and the visibility step passes `include_stars: true` so the bundled bright-star catalog is no longer silently omitted. ([#22](https://github.com/cyanheads/astronomy-mcp-server/issues/22))
- **Zoneless timestamps** — a `time`/`start`/`stop` value carrying no `Z` or numeric offset is now read as UTC, matching every tool's documented contract, instead of the server process's local `TZ`. Covers `astronomy_get_sky_position`, `astronomy_get_moon_phase`, `astronomy_list_visible`, `astronomy_get_rise_set`, `astronomy_find_events`, `astronomy_get_satellite_passes`, and `astronomy_get_ephemeris`, whose default-`stop` computation and range-order guard bypassed the shared parser and needed the same fix directly. ([#26](https://github.com/cyanheads/astronomy-mcp-server/issues/26))
