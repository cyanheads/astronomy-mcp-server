# 0.2.2 — 2026-07-30

## Fixed

- **Every tool's `format()`** — a numeric value now renders as `<rounded display> [<exact>]`, with the bracketed tail dropped when the rounding already round-trips, so a `content[]`-only client can recover what `structuredContent` carries. Fraction-to-percentage fields (`illuminated_fraction`, `obscuration`) label the tail as a fraction, since that rendering changes the unit as well as the precision. Distances in AU moved from fixed decimals to significant figures — a fixed count broke at both ends of the range: the Moon in `astronomy_list_visible` read `0.003 AU` (13% high), and a low-orbit `astronomy_get_ephemeris` target read `0.0000 AU`. `astronomy_list_visible` is the one exception: tailing all eleven per-body coordinates grew its `content[]` ~1.7x on every call, so its scan line keeps only the distance's tail — `astronomy_get_sky_position` returns the same field set with every exact value for any body it lists. `astronomy_get_ephemeris` also stopped rendering a literal `az undefined°` for a point carrying altitude without azimuth; it now reads `az n/a`. ([#14](https://github.com/cyanheads/astronomy-mcp-server/issues/14))
- **`astronomy_stargazing_plan`** — the workflow asked whether the Moon is above the horizon but only ever called the geocentric `astronomy_get_moon_phase`, which can't answer that. Added `astronomy_get_rise_set` with `body: "moon"` as its own step, renumbered the chain to six steps, and updated the closing summary to ask for both the Moon's brightness and the hours it's above the horizon. ([#16](https://github.com/cyanheads/astronomy-mcp-server/issues/16))
