# 0.2.3 — 2026-07-30

## Fixed

- **`astronomy_get_ephemeris`** — a row Horizons returned without a distance was kept as `distance_au: NaN`, which the output schema rejects and failed the whole call, discarding every row that had parsed. `parseRow` now drops such a row the same way it already drops one with no date or no RA/Dec; a non-numeric position column (an unparseable token, not `n.a.`) closed the same gap through `ra_hours`/`dec_degrees` and is fixed the same way. When a row is dropped, the output carries a `dropped` count (present only when at least one row was discarded) and `notice` names the resulting gap; the two compose into one `notice` when a discard coincides with truncation. A response with no usable rows now surfaces the tool's own `horizons_unavailable` contract, whose recovery hint leads with what was actually missing. ([#18](https://github.com/cyanheads/astronomy-mcp-server/issues/18))
- **`astronomy_get_ephemeris`** — the `invalid_step` error message listed only `m`, `h`, or `d`, but the validator also accepts `mo` and `y`; the message now names all five.
