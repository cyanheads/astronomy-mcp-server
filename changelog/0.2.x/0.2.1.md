# 0.2.1 — 2026-07-30

## Fixed

- **`astronomy_get_ephemeris`** — the truncation-disclosure notice was computed but never reached a client: it wasn't declared in the `enrichment` block, so the effective-output parse stripped it from both `structuredContent` and `content[]`. `notice` is now a declared enrichment field, populated via `ctx.enrich.truncated({ shown, cap, guidance })`; the guidance names the exact instant the returned rows end at and tells the caller to re-call from there or split the range into smaller adjacent spans at the same step, rather than widening the step and losing samples. ([#11](https://github.com/cyanheads/astronomy-mcp-server/issues/11))
- **`astronomy_get_ephemeris`** — a lone `latitude` or `longitude` silently fell through to a geocentric query, dropping the observer and its alt/az columns; a `stop` at or before `start` and a malformed `step` were both forwarded to Horizons instead of rejected locally. All three now fail fast with dedicated `incomplete_observer`, `invalid_time_range`, and `invalid_step` contract entries before any upstream request. The step pattern accepts every calendar unit Horizons supports — `m`, `h`, `d`, `mo`, `y` — not just the three the description previously used as examples. ([#13](https://github.com/cyanheads/astronomy-mcp-server/issues/13))
- **`astronomy_get_satellite_passes`** — a window opening mid-pass reported `start` as the pass's `rise_utc` with a clipped duration instead of the satellite's real acquisition time. `predictPasses` now requires a genuine below-to-above transition (checking the sample one step before `start`) before opening a pass, so a pass already underway is omitted — a pass rising exactly at `start` is still kept, so feeding a previously reported `rise_utc` back in as `start` never loses it. ([#12](https://github.com/cyanheads/astronomy-mcp-server/issues/12))
- **`astronomy_get_satellite_passes`** — an element set SGP4 can no longer propagate (a reentered object, or a `start` outside the set's validity window) silently produced `passes: []`, indistinguishable from "nothing visible tonight." `predictPasses` now probes the first instant of the window and rejects up front, naming the cause by epoch distance: `object_decayed` when the window sits within about a month of the element set's epoch, `time_out_of_range` when `start` is further out. `communityDecayCheckEnabled: true` is set on every `propagate()` call. ([#17](https://github.com/cyanheads/astronomy-mcp-server/issues/17))
