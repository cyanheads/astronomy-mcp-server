# 0.2.6 — 2026-08-18

## Fixed

- **`astronomy_get_ephemeris`** — the truncation notice advertised an inclusive resume instant: JPL Horizons' `START_TIME` is inclusive of the first output row, so re-calling at the last returned row duplicated it. The notice now advertises the instant one step past the last row, computed from the parsed `step` (fixed-duration for `m`/`h`/`d`, calendar-stepping for `mo`/`y`). ([#11](https://github.com/cyanheads/astronomy-mcp-server/issues/11))
- **`astronomy_get_ephemeris`** — `HorizonsService.buildUrl()` now sets `APPARENT=REFRACTED` on a topocentric request. `APPARENT` defaults to `AIRLESS`, so `altitude_degrees` was geometric rather than the refraction-corrected value the field already advertised — a gap of up to ~0.5° near the horizon, matching the core sky-position tools. ([#21](https://github.com/cyanheads/astronomy-mcp-server/issues/21))
- **`astronomy_get_satellite_passes`** — the documented `MAX_EPOCH_DISTANCE_DAYS` (30) horizon was only enforced when SGP4's own propagation probe happened to refuse a `start` instant; past the horizon SGP4 often keeps returning well-formed positions from mean elements that no longer describe the orbit. `predictPasses()` now checks the epoch distance independently, before probing propagation, and rejects an out-of-range `start` with `time_out_of_range` regardless of what the probe would have returned. ([#27](https://github.com/cyanheads/astronomy-mcp-server/issues/27))
