# 0.2.0 — 2026-07-30

## Added

- **`astronomy_find_events`** — `perigee_apogee` accepts `body: "earth"`, returning its heliocentric perihelion/aphelion; gated to this one event class, still rejected for the observer-relative tools and every other event. ([#10](https://github.com/cyanheads/astronomy-mcp-server/issues/10))
- **`astronomy_find_events`** — `conjunction` on `mercury`/`venus` now returns both the inferior and superior pass per synodic period, labelled by the new `conjunction_kind` output field (`inferior`/`superior`). ([#7](https://github.com/cyanheads/astronomy-mcp-server/issues/7))
- `.gitattributes`, `.github/FUNDING.yml`, `.github/SECURITY.md` — line-ending/binary/generated-file normalization, a funding link, and a private vulnerability-reporting policy.
- `bunfig.toml` — `@socketsecurity/bun-security-scanner` wired into `[install.security]` to scan every package before install; `minimumReleaseAge` blocks installing a package version published less than 3 days ago, with `@cyanheads/mcp-ts-core` excluded for same-day framework adoption.
- `.env.example` documents `MCP_LOG_RATE_LIMIT_THRESHOLD` / `MCP_LOG_RATE_LIMIT_WINDOW_MS`, the framework's per-level log rate limiting.

## Changed

- **`astronomy_find_events`** — body-relative event descriptions and the `body` field's `.describe()` now name exactly which bodies each event class accepts (superior planets for `opposition`, any planet for `conjunction`, mercury/venus for `max_elongation`, moon/earth/planet for `perigee_apogee`), and clarify that `latitude`/`longitude` apply only to `solar_eclipse`.
- **`horizons-service` / `satellite-service`** — read the canonical `status`/`body` error-data fields `@cyanheads/mcp-ts-core` 0.11.0 adds alongside the existing `statusCode`/`responseBody` aliases, so the upstream-leak guard covers both. The satellite service's CelesTrak fetch passes `expectedStatuses: [404]` so an uncatalogued object logs at debug instead of error. Both services now map a fetch-deadline `Timeout` to their own typed unavailable contract instead of bubbling the framework's code.
- Dockerfile pins `oven/bun:1.3.14` in both stages (was floating `1.3`/`1.3-slim`), adds BuildKit cache mounts for `bun install`, and passes `--ignore-scripts` on the build-stage install and the conditional OpenTelemetry `bun add`.
- `.gitignore` anchors `data/` to the repo root (`/data/`) instead of matching any nested `data/` directory.
- `scripts/clean-mcpb.ts` / `scripts/lint-packaging.ts` strip and verify a second bundle-entry class — platform-specific native bindings (`@duckdb/node-bindings-*`) — alongside the existing dependency-shipped agent docs, so a `.mcpb` build no longer locks to the platform it was packed on.
- `package.json` `author` field: `cyanheads <casey@caseyjhand.com> (...)` → `Casey Hand <casey@caseyjhand.com> (https://caseyjhand.com)`.

## Fixed

- **`astronomy_find_events`** — `opposition` and `conjunction` returned each other's time for every planet: the relative longitude passed to astronomy-engine's `SearchRelativeLongitude` was inverted (0 is opposition for a superior planet, 180 is conjunction — not the reverse). `opposition` now also rejects mercury and venus, which never reach it. ([#7](https://github.com/cyanheads/astronomy-mcp-server/issues/7))
- **`astronomy_get_moon_phase`** — `age_days` over-reported by ~29.53 days for roughly the first 1.5 days after a new moon: the backward-search window could return the new moon *before* the most recent one. `moonAgeDays` now searches a full synodic month forward from the look-back point and takes the later of the (at most two) new moons found that is still at or before the query time. ([#8](https://github.com/cyanheads/astronomy-mcp-server/issues/8))
- **`astronomy_find_events`** — an unsupported body for a body-relative event (e.g. `opposition`/`sun`, `perigee_apogee`/`sun`) threw astronomy-engine's raw internal error (JSON-RPC `-32603`, no recovery hint) instead of a validation error. Every body-relative event class (`opposition`, `conjunction`, `max_elongation`, `perigee_apogee`) now validates its body against the set that class is actually defined for before calling the engine, throwing `body_not_supported` with a hint naming the valid alternatives. ([#9](https://github.com/cyanheads/astronomy-mcp-server/issues/9))
- **`astronomy_find_events`** — the tool description claimed both solar and lunar eclipses take an observer and report local visibility; only solar eclipses do — lunar eclipses are geocentric and return no `local_visible`. Description and output field docs now match the implemented contract. ([#15](https://github.com/cyanheads/astronomy-mcp-server/issues/15))
