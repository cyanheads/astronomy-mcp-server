# 0.2.4 — 2026-08-18

## Added

- `.github/CONTRIBUTING.md` and `.github/CODE_OF_CONDUCT.md`.

## Changed

- `.github/SECURITY.md` — vulnerability-report contact is `security@caseyjhand.com`, not the personal address.
- `Dockerfile` production installs pass `--omit=peer` on both the base install and the OpenTelemetry step, dropping framework peer tiers this server never imports at runtime.
- `tsconfig.json` / `tsconfig.build.json` split so `tests/` typechecks under `devcheck`.

## Fixed

- **`astronomy_get_ephemeris`** and the five core tools — a calendar date that does not exist (`2026-02-30`) rolled forward into the next month instead of failing. `EphemerisService.resolveTime()` and the tool's own `start`/`stop` guards now reject it with `invalid_time`, validated against the full proleptic-Gregorian leap rule. ([#23](https://github.com/cyanheads/astronomy-mcp-server/issues/23))
- **`resolveTime()`**'s `invalid_time` throw now carries its recovery hint inline, reaching `structuredContent.error.data.recovery.hint` and the `Recovery:` line in `content[]` — previously the reason surfaced with no hint. ([#5](https://github.com/cyanheads/astronomy-mcp-server/issues/5))
- **`invalid_time`** and **`invalid_timezone`** are now declared in `errors[]` on all five core tools, and `invalid_timezone` on `astronomy_get_satellite_passes` — both reasons were already thrown; they're now part of the typed contract.

## Dependencies

- `@cyanheads/mcp-ts-core` `^0.11.0` → `^0.11.5`
- `@biomejs/biome` (dev) `2.5.5` → `2.5.8`
- `@types/node` (dev) `^26.1.2` → `^26.2.0`
