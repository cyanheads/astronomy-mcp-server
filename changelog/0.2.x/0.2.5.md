# 0.2.5 — 2026-08-18

## Added

- **`name` input** on `astronomy_get_satellite_passes` resolves a satellite name to a catalog ID against CelesTrak's `NAME=` query, mutually exclusive with `norad_id`. An ambiguous match returns `ambiguous_satellite_name` with up to 20 candidates ordered by catalog number, `match_count`/`shown`/`truncated` fields, and a hint that leads with narrowing when the list is capped; a new `resolved_from_name` output field echoes the query that resolved it. ([#19](https://github.com/cyanheads/astronomy-mcp-server/issues/19))

## Changed

- **`astronomy_get_satellite_passes`** now fetches CelesTrak's GP data as `FORMAT=JSON` (OMM) instead of `FORMAT=TLE`, propagated via `satellite.js`'s `json2satrec`. TLE cannot encode catalog numbers above 99999, so six-digit objects — over a hundred current Starlink satellites among them — were previously unreachable and misreported as `tle_not_found`. ([#25](https://github.com/cyanheads/astronomy-mcp-server/issues/25))

## Fixed

- **`astronomy_get_satellite_passes`** — a GP record that parses as JSON but fails OMM validation now throws a new, non-retryable `malformed_element_set` reason instead of being reported as the retryable `celestrak_unavailable` outage. ([#28](https://github.com/cyanheads/astronomy-mcp-server/issues/28))
