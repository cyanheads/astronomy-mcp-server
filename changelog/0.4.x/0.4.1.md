# 0.4.1 — 2026-10-08

## Changed

- **Docker image** — a `deps` stage on `$BUILDPLATFORM` cross-installs production dependencies with `--os`/`--cpu`, where the production stage previously ran `bun install` on the target platform; a multi-arch build no longer runs Bun under QEMU. (mcp-ts-core 0.13.10)
- **Docker image OpenTelemetry install** — `scripts/install-otel.ts` installs the OpenTelemetry peers at the framework's declared ranges, through `bunfig.toml`'s release-age gate and scanner. (mcp-ts-core 0.13.10)
- **Docker image musl prune** — `scripts/prune-musl-packages.ts` removes musl-only packages from the glibc runtime image. (mcp-ts-core 0.13.11)
- **Docker image environment** — the unread `MCP_FORCE_CONSOLE_LOGGING` is no longer set (mcp-ts-core 0.13.8); the base image moves from Bun 1.4.0 to 1.4.2 (mcp-ts-core 0.13.7). `.dockerignore` excludes every `.env*` file and the MCP Registry token files.
- **`server.json`** — both npm entries use `runtimeHint: "npx"` with no package arguments, where they used `runtimeHint: "bun"` with `run start:stdio` / `run start:http`; the streamable-http entry sets `MCP_TRANSPORT_TYPE` to `http`. (mcp-ts-core 0.13.11)
- **`astronomy_get_satellite_passes`** — the `time_out_of_range` recovery hint now reads "An element set describes the orbit for weeks either side of its epoch — request a start within about a month of today."
- **Error throw sites** — handlers no longer forward `ctx.recoveryFor(...)` per `ctx.fail`; the framework fills the declared hint (mcp-ts-core 0.13.10). Tests assert the hint on the wire envelope for every bare `ctx.fail` and for the `astronomy://body/{body}` resource's `unknown_body`.
- **`.mcpb` bundle** — `.mcpbignore` excludes `docs/idea.md`, `logs/`, `.cache/`, and `tests/`.
- **Repo files** — `.gitignore` ignores every `.env*` file except `.env.example`, `.env.template`, and `.env.sample`; `codeql.yml` runs one matrix job per language (`actions`, `javascript-typescript`), each under its own `/language:<language>` category.
- **Tooling and skills** — `framework-skills/` and the `devcheck`, `lint:mcp`, `lint:packaging`, skill-version, anti-pattern, and `release:github` scripts are re-synced to mcp-ts-core 0.13.14; `lint:packaging` now checks the Dockerfile build platform and the `server.json` npm launch shape.
- **Docs** — the README tool, feature, and configuration sections are rewritten against current behavior, and its Docker example runs the default HTTP transport. `CLAUDE.md` and `AGENTS.md` follow the framework's error and context docs. `.env.example` documents `MCP_REQUEST_STATE_KEY`, `LOG_TOOL_FAILURE_PAYLOADS`, `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES`, `LOG_LLM_INTERACTIONS`, and the `OTEL_EXPORTER_OTLP_*_ENDPOINT` variables.
